## 3. 顺带闭合的一个缺口

上一轮我标记过："记录编号 → 具体模式的映射（rec6/7 = 1080p60 高/标准）沿用旧读法，没有独立复核"。
这次实测把它**从数据侧反向确证**了：

- 1080p60「标准」实测 50.8 Mbps ≈ 新 avg 48、max 56 → 落在 rec7（原 28/24 → 56/48）✓
- 1080p30「标准」实测 25.5 Mbps ≈ 新 avg 24、max 28 → 落在 rec11（原 14/12 → 28/24）✓
- 25p / 24p 同样对应 rec13 / rec15 ✓

所以 `0x10717144` 那张表里 rec6–15 = 1080p 60/50/30/25/24 的高/标准两档，现在是**实测确认**，不是推断。

## 4. bitrate-b 还没试（要不要试，取决于你）

`build/sd/bitrate-b/` 把 1080p「高」档再往上推：

| 帧率 | 高 档 现状（= bitrate-a 之后的高档仍是原值） | bitrate-b 后 |
|---|---|---|
| 60/50p | 56/48 | **84/70**（Z30 实机验证过的值） |
| 30/25/24p | 28/24 | **56/48** |
| 全部「标准」档 | 已提到高档原值 | 再提一档（同上） |

考虑：

- 84 Mbps @ 1080p60 = 10.5 MB/s → **UHS-I V30 卡足够**（V30 = 30 MB/s）
- Z30 在同构表上实测过 84/70，但 Z fc 的编码器/散热没验证
- 副作用：卡上「剩余时间」估算会更偏离实际（Z30 也记录了这个）
- 失败模式：按下录制立刻中断，或录几分钟后停 → 回滚 `stock` 即可，不会变砖

# 追加：bitrate-b 实机验证通过（2026-10-25 晚）

`build/sd/bitrate-b/EG198581.BIN` 刷入后按优先级测了三个格式（1080p 高档）：

| 片段 | 格式 | 目标 max/avg | 实测 Data rate | 相对 avg |
|---|---|---|---|---|
| ZFC_3089 | 1080p 59.94 高 | 84/70 | 70,245 kbps | **+0.4%** |
| ZFC_3090 | 1080p 29.97 高 | 56/48 | 44,828 kbps | −6.6% |
| ZFC_3091 | **3840×2160 29.97 高** | 144/120（**未改**） | 131,048 kbps | +9.2% |

**判读：全部符合预测。**

- 60p 高档实测 70.2 Mbps，几乎正好等于新 avg（70）→ 84/70 生效
- 30p 高档 44.8 Mbps，略低于 avg 48、远高于原厂 max 28 → 生效；偏低属 VBR 在简单场景下的正常欠冲
- **4K 对照组 131 Mbps**：落在原厂 avg 120 / max 144 之间，与"未改动"一致

**对照组的价值**：4K 原厂就在跑 131 Mbps，说明**卡速和编码器通路能扛住 131 Mbps**，
所以 1080p60 的 84 Mbps 对硬件是小菜。万一 60p 出问题，就只能是 1080p 路径特有的限制，
不会是"码率太高"。这次三项全过，这个疑虑可以消掉了。

**仍未验证**：50p / 25p / 24p 高档（与 60p / 30p 同路径，风险低于已测项）。
如果以后要发布，建议至少补 50p 一个（PAL 变体最容易暴露帧率相关限制）。

# 组合镜像（2026-10-25）

`build/sd/combo/EG198581.BIN` = **慢动作 25 分钟 + bitrate-b + 照片斑马纹**，
23 处改动、88 字节 payload，五道闸门通过，CRC 残差 0。

| 功能 | 位置 | 值 |
|---|---|---|
| 慢动作上限 | `0x102A0470` | 1,500,000 ms（25 分钟） |
| 1080p 码率（rec6–15） | `0x10717144` 表 | 高档 84/70 与 56/48；标准档 56/48 与 28/24 |
| 照片斑马纹 | `0x101765DE` / `0x1017670A` | `9db1` → `00bf` |
| 4K（rec0–5） | 未动 | 144/120、72/60 |

生成方式（可复现）：

```powershell
python tools/combine_patches.py --name combo --spec patches/slowmo25.json patches/bitrate-b.json patches/zebra-photo.json
python make_update.py build --spec patches/combo.json --label combo
```

`tools/combine_patches.py` 会拒收重叠/冲突的改动，并对每条 `expected` 重新核对原厂字节，
所以合成镜像不会建立在过期假设上。
